# Spec vs 実装 差分レビュー

spec/ の設計書と実際のコードを照合し、「実装漏れ」と「仕様と異なる実装」を洗い出した結果です。

---

## A. 実装漏れ（specに書いてあるが未実装）

### A-1. 進化バランステスト（CI組み込み）
- **spec-03**: `test_evolution_distribution()` で10,000回シミュレーションし、各成体の出現回数が200〜4000であること・成体ベクトル同士のコサイン類似度 > 0.95 のペアに警告を出すテストを「実装必須・CI組み込み」と記載
- **実装**: 存在しない。テストは `all_species_have_unique_idle_art` と `all_species_have_action_art` の2つのみ

### A-2. 図鑑に死因が表示されない
- **spec-04** (4.6 図鑑画面): `#001 コロコロ (˘ω˘) ✓ 3日間生きた : 42kg（ガリ）` の下に `落雷に散った` のような死因を表示
- **実装**: `cause_of_death` はセーブデータに保存されているが、`album.rs` のレンダリングでは表示されていない

### A-3. 図鑑にアスキーアートの顔が表示されない
- **spec-04** (4.6 図鑑画面): 各種族名の横に `(˘ω˘)` のような小さいアスキーアートを表示
- **実装**: 種族名のみ表示し、アスキーアート顔は表示されていない

### A-4. なかよし（bond）が表情・セリフに影響しない
- **spec-03** (口調タイプ): 「なかよしが高いほどポジティブ寄りのセリフが選ばれやすい」
- **spec-04** (4.3 表情表現): 「なかよし 高い」で独自のリッチな表現（「きた！きた！」「まってたよ！」など）
- **実装**: `pick_idle_speech` も `get_reaction` も `mood_level(kimochi)` のみ参照。`nakayoshi` は表情やセリフ選択に一切影響しない

### A-5. 「最長生存記録」更新時のメッセージ
- **spec-02** (3.6 死亡・リセット): 「最長生存記録を更新するとメッセージが出る」
- **実装**: `records.longest_survival_ticks` は更新されるが、更新時にメッセージを表示する処理がない

### A-6. 体重関連ランダムイベント
- **spec-02** (3.2 体重): 「好物を食べた (+1〜+3kg)」「走り回っていた (-1〜-2kg)」のイベントが体重変動の仕様に記載
- **実装**: `POSITIVE_EVENTS` に体重を変動させるイベントがない

### A-7. 放置時の体重変化量がspecより約10倍小さい
- **spec-02** (3.2): 放置時の体重変化は `±0.1kg/tick`
- **実装**: `rng.gen_range(-0.1..0.1) * sqrt_ticks * 0.1` — 末尾に `* 0.1` が余分にかかっており、実質 `±0.01/sqrt(tick)` 程度。60tick経過で spec では最大 ±6kg 変動しうるが、実装では約 ±0.077kg しか変動しない

### A-8. ロールバック検知時のUI警告表示がない
- **spec-02** (3.1): 「ローカル時刻の巻き戻しを検知した場合はゲーム進行を行わない」
- **実装**: `rollback_detected` フラグは設定されゲーム進行はスキップされるが、ユーザーへの警告メッセージ表示がない

### A-9. 種族ごとのセリフ個性がない
- **spec-03** (キャラクターの個性方針): 「同じ口調タイプ内でもセリフの内容・ネタは形態ごとに異なる」
- **実装**: `voice.rs` ではVoiceType単位で共通のセリフプールを使用。同じVoiceType（例: Tameguchi）の全種族がまったく同じセリフを返す。種族固有の台詞バリエーションがない

### A-10. セリフパターン数が大幅に不足
- **spec-03** (口調タイプ): 「1ファイル20〜30パターン」
- **実装**: 各(voice_type, action, mood)の組み合わせにつき **4〜5パターン** しかない。specの20〜30パターンに対して約1/5

### A-11. Stage3のアートと進化データの不整合（到達不能種族20体）
- **ascii_art_s3.rs**: 100種のアスキーアートが存在
- **evolution.rs**: Stage3は80種のみ定義（進化ベクトル・allowed_fromあり）
- 残り20種はアートがあるが進化パスがなく、ゲーム中に到達不能

### A-12. 体型カテゴリが未実装
- **spec-03**: 10種の体型カテゴリ（まるっこ系、ながい系、ひろい系等）を定義
- **実装**: `BodyType` 列挙型やフィールドが存在しない。アスキーアートとしては視覚的に反映されているが、データとして形式化されていない

### A-13. アニメーションフレームワーク
- **spec-03** (アスキーアートとアニメーション):
  - 呼吸（体の上下1行シフト）、左右移動、まばたき（`ω` → `－` → `ω`）、尻尾・耳の揺れ
  - 呼吸 2〜4fps、アクション時 6〜8fps、進化演出 8fps
  - ファイル構造として `assets/ascii/{monster_id}/` ディレクトリ構想
- **実装**: アニメーションはフレーム切り替えで実装されているが、「呼吸＋もう1種類の組み合わせ」というレイヤード方式ではない。`assets/` ディレクトリは存在せず、全てのアートがRustソースコード内に直接記述されている。FPSもメインループで約2fps（500msタイマー）固定

## B. 仕様と異なる実装（specの内容と差がある部分）

### B-1. 種族数が仕様と異なる
| 段階 | spec | 実装 |
|------|------|------|
| Stage 1（赤ちゃん） | **8種** | **10種**（ピリリ, モグモが追加） |
| Stage 2（子供） | **40種**（5タイプ × 各8種） | **30種**（5タイプ × 各6種） |
| Stage 3（成体） | **100種以上** | **80種** |
| Stage 4（突然変異） | **5〜8種** | **8種** |
| **合計** | **150種以上** | **128種** |

### B-2. Stage2 → Stage3の進化ロジック
- **spec**: コサイン類似度が最も高い成体に進化（最上位1体が確定進化）
- **実装**: 上位3体から重み付きランダムで選択（多様性のため）。specの「最もコサイン類似度が高い成体に進化する」とは異なるが、これは意図的な改善と思われる

### B-3. メイン画面のヘッダー表示
- **spec-04** (4.2): ヘッダーに `コロン` （ニックネームのみ）を表示
- **実装**: `コロン（ドタン）` のように種族名も括弧付きで表示

### B-4. メイン画面で体重ラベルが表示される
- **spec-04** (4.2): ヘッダーに `⚖ 84kg` のみ表示
- **実装**: `⚖ 84kg (ガリ)` のようにラベルも括弧付きで表示（ラベルはspec上は図鑑のみで表示）

### B-5. 起動画面の経過時間ラベル
- **spec-04** (4.5): `Calculating time passed: 8時間 12分` （英語ラベル）
- **実装**: `経過時間: 8時間 12分` （日本語ラベル）

### B-6. ランダムイベントの発動タイミング
- **spec-02** (3.4): 「起動時（経過時間に応じた回数）にランダムに発生」
- **実装**: 起動時のみ実行（spec通り）。アクション実行時の時間チェックではイベント抽選は行われない。ただし最低1回のロール保証 (`(elapsed_ticks / 60).max(1)`) があり、1時間未満の経過でもイベントが発生しうる

### B-7. 事故確率の単位計算の違い
- **spec-02**: 「1ティックあたりの事故確率」で計算
- **実装**: 1時間（60ティック）をまとめて `1 - (1 - p_per_tick)^60` で集約計算。結果的な確率は同等だが、計算方式が異なる

### B-8. アクションのラベル表記
- **spec**: 「いっしょに遊ぶ」「特訓する」「まったりする」
- **実装**: 「あそぶ」「特訓」「まったり」（簡略化されている）

### B-9. 事故確率の日齢下限
- **spec-02**: `日齢 × 0.00347%` — 日齢0のペットは事故確率0
- **実装**: `day_age = (age_ticks / 1440.0).max(1.0)` — 日齢を最低1.0にクランプしているため、生まれたてのペットにも1日目相当の事故確率がかかる

### B-10. 進化タイミングが固定値
- **spec-03**: Stage1→2は「6〜12時間後」、Stage2→3は「24〜48時間後」（範囲指定）
- **実装**: `STAGE2_TICKS = 360`（固定6時間）、`STAGE3_TICKS = 1440`（固定24時間）。常に範囲の下限で進化する

### B-11. アクション時のFPSが低い
- **spec-03**: アクション時アニメーション 6〜8fps、進化演出 8fps
- **実装**: 全てのアニメーションが約2fps（500msタイマー）で統一

### B-12. 野生型の条件
- **spec-03**: 「Stage1の間に一度もアクションをしなかった」
- **実装**: `max_score == 0`（全タイプスコアが0）で判定。Talk（`T`）はタイプスコアを変動させないため、Talkだけ実行した場合はspecでは野生型ではないが実装では野生型になる…と思われるが、Talkはタイプ傾向に影響なし(`なし`)と spec にも書いてあるため、実質的に差はない

## C. 軽微な差異（問題にはなりにくいもの）

| 項目 | spec | 実装 | 備考 |
|------|------|------|------|
| 図鑑の合計数表示 | 固定 `150+` | 動的に `all_species_names().len()+` | 現在は `128+` と表示される |
| アクションリアクションの「」付き | 「 あ、きた！ 」 | UI層では括弧なし（テキスト自体に含まれている場合あり） | voice.rs のテキストには「」が含まれているため実質OK |
| デバッグ図鑑 | specに記載なし | `[D]デバッグ図鑑` がdebugビルドに存在 | 開発用の追加機能 |
| アクションアニメーション画面 | specに記載なし | `ActionAnimation` モード（2.5秒の中間画面）が存在 | specを超えた追加演出 |
| 起動画面のタイトルバナー | specに記載なし | `Tamimon` のシアン色バナーが表示される | 追加演出 |
| `last_stage4_check` フィールド | specに記載なし | PetDataに追加 | Stage4判定用の内部実装詳細 |
| Time API のサービス | WorldTimeAPI (worldtimeapi.org) | timeapi.io | 別のAPIサービスだが同等の機能 |
| イベント最低1回ロール | 経過時間に比例した回数 | `(elapsed_ticks / 60).max(1)` | 短時間でも最低1回抽選される |

## 対応優先度の提案

### 高（ゲーム体験に直接影響）
1. **A-4**: なかよしがセリフ・表情に影響するようにする（specの根幹設計）
2. **A-9**: 種族ごとのセリフ個性を追加する（specの「一体一体が固有の存在」設計）
3. **A-2**: 図鑑に死因を表示する（既にデータは保存されているので表示のみ）
4. **A-5**: 最長生存記録更新メッセージ（死亡画面で表示）
5. **A-7**: 放置時の体重変化量を修正（`* 0.1` の除去）
6. **A-11**: Stage3の到達不能20種を修正（進化データの追加 or アートの削除）

### 中（ゲームの完成度向上）
7. **A-10**: セリフパターン数を増やす（現状4〜5 → 目標20〜30）
8. **A-3**: 図鑑にアスキーアート顔を表示
9. **A-6**: 体重変動ランダムイベントの追加
10. **B-1**: 種族数をspec目標に近づける（特にStage2: 30→40, Stage3: 80→100+）
11. **B-9**: 事故確率の日齢下限 — 日齢0では事故確率0にする
12. **B-10**: 進化タイミングに範囲を持たせる（固定値→ランダム範囲）
13. **A-8**: ロールバック検知時の警告表示

### 低（品質向上・テスト・演出強化）
14. **A-1**: 進化バランステストの追加
15. **B-11**: アクション時のFPSを上げる（2fps → 6〜8fps）
16. **A-13**: アニメーションの充実（レイヤード方式は工数が大きい）
17. **A-12**: 体型カテゴリのデータ化（ゲームプレイへの影響はないが図鑑等で活用可能）
18. **B-8**: アクションラベルの表記をspecに合わせる
